# Activity-Relay Directory 0.1.0-rc3

Status: release-candidate source draft. RC2 passed clean-room and real-browser
acceptance but was intentionally not tagged or published after operator review
identified final public-presentation refinements. RC2's canonical run-121 bytes
remain frozen and are not relabeled as RC3.

## Version identity

- Git tag: `v0.1.0-rc3`
- Application version: `0.1.0-rc3`
- Debian package version: `0.1.0~rc3-1`
- Previous published candidate: `v0.1.0-rc1` (immutable)
- Accepted but unpublished predecessor: `0.1.0-rc2`
- First eventual stable version: `1.0.0` / Debian `1.0.0-1`
- There will be no final `v0.1.0` tag.

## Candidate scope

RC3 carries forward RC2's accepted reverse-proxy CSP correction, bundled public
stylesheet, Activity-Relay-family presentation, accessibility cues, lifecycle
protocol, schema version 7 storage behavior, moderation, retention, growth
guard, and candidate-generic release workflow.

The new source delta is deliberately presentation/configuration focused:

- optional operator website and public email links;
- an explicit Fediverse `@user@host` plus explicit HTTPS profile URL pair;
- complete suppression of absent operator details;
- no derivation of Fediverse profile URLs;
- no operator metadata in `/v1/relays` or `/v1/status`;
- removal of visible JSON API navigation while retaining the JSON API itself;
  and
- removal of the standalone privacy-boundary panel without changing the bounded
  public projection.

## Operator YAML

The optional default file is `/etc/activity-relay-directory/config.yml`.
`DIRECTORY_CONFIG_PATH` selects an alternate clean absolute path. A missing
default file is valid and renders no operator links. Unknown fields and invalid
public links fail closed when configuration is present.

The package owns the empty `/etc/activity-relay-directory/` parent directory and
installs its example under
`/usr/share/doc/activity-relay-directory/examples/config.yml.example`, while
leaving `/etc/activity-relay-directory/config.yml` operator-owned and absent by
default. Installation therefore publishes no placeholder contact details.

The stock container image also creates the empty default operator-config
directory and carries the same example under `/usr/share/doc/`; no active
operator configuration is baked into the image. `compose.yml` forwards
`DIRECTORY_CONFIG_PATH` but binds no operator file by default.

## Acceptance

RC3 requires a new exact canonical build from its reviewed signed source commit;
the accepted RC2 build must not be reused under the RC3 name. Development and
clean-room validation should focus on the new YAML and public presentation while
retaining the established package/container/CSP safety boundaries. Real-browser
acceptance should verify configured and unconfigured operator-link states.

Tagging, release publication, deployment activation, and any production
operator-contact values remain separate explicit gates.
