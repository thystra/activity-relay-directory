## Candidate scope

The RC4 source delta is intentionally restricted to documentation and release
version metadata. It does not alter Go runtime source, Dockerfile/Compose
behavior, operator example configuration, release/build workflows, package
scripts, systemd service hardening, or package default runtime configuration.

The substantive correction is in `docs/PUBLIC-LISTING.md`: unknown fields and
structural operator-file failures remain startup-fatal, while a successfully
parsed file containing malformed Nice-to-have values or an incomplete
Fediverse pair does **not** stop the core service. Unsafe or partial values are
suppressed and deterministic diagnostics are rendered only on the human
Directory page.

RC3's release note is also updated to record its final NO-GO disposition rather
than leaving the candidate described as still in progress.

## RC4 acceptance strategy

RC4 must still be built as a new canonical artifact set from the exact reviewed
RC4 commit; RC3 bytes must not be relabeled.

Before promotion, prove that the RC3-to-RC4 changed-path set remains restricted
to the reviewed documentation/release-version metadata allowlist and run the
normal source validation. Then bind the new RC4 artifacts to that commit,
confirm the corrected `PUBLIC-LISTING.md` is present in the Debian package, and
perform focused Debian/Docker runtime smoke checks plus a short real-browser
presentation check. Replaying the exhaustive 40-case runtime matrix is not
required unless the reviewed source delta expands beyond the allowlist or a
focused check reveals a discrepancy.

Tagging, release publication, deployment activation, restoration of normal APT
maintenance on the shared validation VM, and creation of the next shared VM
baseline remain separate explicit gates.
