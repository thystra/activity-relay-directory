# Activity-Relay Directory 0.1.0-rc1

Status: release-candidate draft. This document is committed before publication;
the candidate is not released until the separate tag/publication gate succeeds.

## Version identity

- Git tag: `v0.1.0-rc1`
- Application version: `0.1.0-rc1`
- Debian package version: `0.1.0~rc1-1`
- First eventual stable version: `1.0.0` / Debian `1.0.0-1`
- There will be no final `v0.1.0` tag.

## Candidate scope

This is the first packaged pre-1.0 candidate of Activity-Relay Directory. It
contains the completed version-1 lifecycle protocol, durable SQLite persistence
through schema version 7, moderation, health projection, reversible soft
pruning, default-zero inactive retention, bounded public JSON/HTML views,
database-growth safeguards, local administration, and the reviewed Go 1.26
toolchain policy.

## Installation safety

The Debian package installs the service disabled and does not start it.
Fresh defaults bind to loopback and keep lifecycle, public listing, automatic
soft pruning, positive inactive retention, and administrator email disabled.
No reverse proxy, DNS, mail recipient, mail credentials, or relay host is
configured by package installation.

RC acceptance exercises both exact canonical installation paths independently.
The Debian test installs the candidate `.deb` while keeping the service
disabled until the explicit activation step. The container test loads the
canonical Docker archive and verifies the image tagged
`activity-relay-directory:0.1.0-rc1` with explicit configuration and its own
state. The two tests must use separate writable SQLite databases and, if run
concurrently, separate loopback ports. Reverse-proxy/public exposure remains a
later explicit approval.

## Persistence / rollback

The current schema is version 7. Before activating the candidate against
valuable state, take and restore-test a matching backup. Downgrade is not
supported in place; restore the database backup created for the older binary.

Package removal or purge does not automatically delete
`/var/lib/activity-relay-directory`. Destructive state removal is a separate
manual operation after backup review.

## Artifact authority

Forgejo is authoritative. The manually dispatched Forgejo release workflow
builds one canonical artifact set from an exact reviewed commit. The set
contains the `.deb`, standalone binary, CycloneDX SBOM, build metadata,
`SHA256SUMS`, and a Docker-loadable `linux/amd64` image archive tagged
`activity-relay-directory:0.1.0-rc1`. The candidate must be independently
install-tested from both the exact `.deb` and exact container archive before
tagging and publication. Forgejo and GitHub releases receive those same bytes;
GitHub does not independently rebuild any official release asset or image.
