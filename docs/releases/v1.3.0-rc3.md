# Activity-Relay Directory 1.3.0-rc3

- Application version: `1.3.0-rc3`
- Debian package version: `1.3.0~rc3-1`
- SQLite schema: `11`
- `/v1/status` schema: `4`
- `/v2/relays` schema: `5`

RC3 hardens the public lifecycle boundary and adds optional receiving-site
telemetry without changing operational eligibility or tier semantics.

## Protocol and storage

Protocol v2 relay self-report accepts `participation_mode` only as empty,
`open`, `restricted`, or `closed`. Register and heartbeat may carry a bounded
`telemetry.receiving_instance_count` value; unregister remains identity-only.
Malformed or semantically invalid requests are rejected before untrusted values
are applied. Telemetry is stored separately in schema 11 and never influences
reachability, moderation, enrollment, pruning, eligibility, or tiers.

Remote strings remain data: persistence uses parameterized SQLite operations,
public HTML is template-escaped, protocol bodies are bounded/strictly decoded,
and shell-backed notification delivery passes validated arguments directly to a
resolved executable without invoking a shell. Regression tests include SQL,
HTML/shell metacharacter, duplicate-member, unknown-member, control-character,
and telemetry-bound cases.

## Public directory

The compact relay row is now `Relay | Registration | Sites | ♥ Heartbeat |
Reachability`. Detailed heartbeat/check timestamps remain in the expanded view.
Registration can be filtered as All/Open/Restricted/Closed, and rows inside each
operational tier are ordered open, restricted, closed, then unreported. The
self-reported receiving-site count is visible on the compact row; absent
telemetry is shown as unreported rather than zero.
