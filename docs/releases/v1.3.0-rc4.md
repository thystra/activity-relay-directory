# Activity-Relay Directory 1.3.0-rc4

- Application version: `1.3.0-rc4`
- Debian package version: `1.3.0~rc4-1`
- SQLite schema: `12`
- Lifecycle protocols: `[1,2,3]` when v3 is configured

## Protocol v3 and telemetry

RC4 adds signed `/v3/relays/*` lifecycle routes. Registration retains the full
normalized relay profile and register/heartbeat may carry the bounded
`participating_instance_count`. Schema 12 stores that count and receipt time
separately from schema 11's `receiving_instance_count`. Public **Sites** prefers
the v3 participating count and falls back to the v2 value while mixed rc3/rc4
clients are present. Migration 0011 is unchanged.

The shared signed v3 registration fixture is consumed by both AR and ARD to
lock the wire contract, including the v3 signature tag.

Every successfully authenticated registration is also fresh liveness evidence.
ARD advances both lifecycle `last_seen_at_unix` and the retained heartbeat
timestamp for create, unchanged/profile-sync, and restore registration outcomes.
Local CSV/discovery/profile writes remain operationally independent and cannot
refresh heartbeat evidence. Public heartbeat health and the human **Last
heartbeat** value use the retained heartbeat timestamp rather than generic
lifecycle last-seen activity.

## Operator presentation

The package-managed reference file is now
`/etc/activity-relay-directory/config.yml.example`; the live `config.yml` is not
created or overwritten. Actionable disabled YAML lines use `#KEY...` and
`#  - ...` formatting so the operator enables them by deleting only `#`.

`DIRECTORY-TITLE` and `DIRECTORY-BANNER-URL` optionally customize the human
Directory. The title is bounded and control-character free. Banner URLs are
bounded absolute HTTPS URLs without credentials; the response CSP admits only
the configured HTTPS origin plus self.

The compact row no longer repeats a heartbeat heart glyph; the `♥ Heartbeat`
heading remains. Registration badges distinguish Open, Restricted, Closed, and
Not reported states.

## CSV import preflight

CSV import prints a processing notice before network probing, calculates a
read-only field-level delta against the retained CSV profile source before
confirmation, lists affected actors/fields, and makes the confirmation prompt
explicitly cover relay discoveries and profile changes. Human results summarize
profile changes as `profile_changes=N` or `profile_changes=none`; JSON retains
the detailed created/updated/cleared/unchanged counters.

An exact actor already retained as an active lifecycle or discovery identity may
receive its CSV profile replacement even if the current actor probe fails. This
does not synthesize reachability or heartbeat evidence and does not change the
relay's operational tier. Unknown candidates still require normal actor
validation or the explicit dead-candidate retention path. CSV
`participation_mode` values used for registration badges/filters remain
case-sensitive in RC4 and should use exact lowercase `open`, `restricted`, or
`closed` (or empty).
